## Block 1 — Java Basics

### Java Kya Hai Aur Kyun

Java ek **strongly-typed, object-oriented language** hai jo JVM (Java Virtual Machine) pe chalti hai — "Write Once, Run Anywhere". Android apps (Java wale) usi JVM-based runtime (ART — Android Runtime) pe chalte hain.

> **Socho Aise:** Java ek factory hai jahan har cheez ka ek fixed blueprint (class) hota hai. Us blueprint se jitne chaho utne products (objects) bana sakte ho — har product blueprint ke rules follow karega.

### 🧠 Theory: Compile Karke Chalta Kaise Hai

Java code seedha CPU nahi samajhta — do steps me chalta hai:

```
YourFile.java  ──(javac compiler)──>  YourFile.class (bytecode)  ──(JVM/ART)──>  Actual execution
```

1. **Compile:** `javac` tumhara `.java` file padh ke usse **bytecode** (`.class` file) me convert karta hai — ye human-readable Java nahi hai, ek intermediate format hai.
2. **Run:** JVM (ya Android me **ART — Android Runtime**) bytecode ko padh ke actual machine instructions me convert karke chalata hai.

> **Yaad Rakho:** Isi do-step process ki wajah se Java "Write Once, Run Anywhere" hai — bytecode kisi bhi OS pe chal sakta hai jahan JVM/ART available hai, chahe original code Windows pe likha ho ya Mac pe.

### 🔬 Hands-On: Java Code Ko Actually Chalao

Android Studio kholne se pehle, plain Java se comfortable ho jao — do tarike hain:

**Option A — Terminal se (agar JDK installed hai):**
```bash
javac BasicsDemo.java      # compile — BasicsDemo.class banega
java BasicsDemo            # run
```

**Option B — Online (bina install kiye):**
[replit.com](https://replit.com) ya [onecompiler.com/java](https://onecompiler.com/java) pe jaake seedha Java code paste karo aur Run dabao — internet browser me hi output dikh jaayega.

> **Tip:** Aaj ke saare code examples yahi tarike se **khud type karke, khud run karke** dekho — sirf padhna kaafi nahi hai. Muscle memory sirf typing se banti hai.

### Data Types Aur Variables

```java
public class BasicsDemo {
    public static void main(String[] args) {
        int age = 25;              // whole number
        double price = 499.99;     // decimal
        char grade = 'A';          // single character
        boolean isActive = true;   // true/false
        long bigNumber = 10000000000L; // bade numbers ke liye

        System.out.println("Age: " + age);
        System.out.println("Price: " + price);
        System.out.println("Grade: " + grade);
        System.out.println("Active: " + isActive);
    }
}
```

| Type | Size | Use |
|------|------|-----|
| `int` | 4 bytes | Whole numbers (age, count) |
| `double` | 8 bytes | Decimal (price, rating) |
| `char` | 2 bytes | Single character |
| `boolean` | 1 bit | true/false flags |
| `long` | 8 bytes | Bade numbers (timestamps!) |
| `String` | — | Text (object, primitive nahi) |

> **Yaad Rakho:** `String` primitive type nahi hai — ye ek **class** hai. Isiliye `String name = new String("Ash")` bhi likh sakte ho (though `"Ash"` direct bhi chalta hai).

### Operators

```java
int a = 10, b = 3;
System.out.println(a + b);   // 13 — Arithmetic
System.out.println(a > b);   // true — Relational
System.out.println(a > 5 && b < 5);  // true — Logical
a += 5;   // a = a + 5 → 15  — Assignment shorthand
```

> **Tip:** Android me `Timestamp` field hamesha `long` (milliseconds) me store karo, `int` nahi — `int` overflow ho sakta hai 2038 ke baad.

## Block 2 — Array, ArrayList, HashMap

### Array — Fixed Size Container

```java
int[] readings = new int[5];   // fixed size 5
readings[0] = 120;
readings[1] = 135;

String[] meterIds = {"MTR-001", "MTR-002", "MTR-003"};
for (String id : meterIds) {
    System.out.println(id);
}
```

> **Warning:** Array ka size **fix** hota hai banne ke baad — na chhota kar sakte na bada. Isiliye real apps me `ArrayList` zyada use hota hai.

### ArrayList — Dynamic List

```java
import java.util.ArrayList;

ArrayList<String> meterList = new ArrayList<>();
meterList.add("MTR-001");
meterList.add("MTR-002");
meterList.remove("MTR-001");
System.out.println(meterList.size());   // 1
System.out.println(meterList.get(0));   // MTR-002

for (String meter : meterList) {
    System.out.println(meter);
}
```

> **Socho Aise:** `Array` ek steel ka dabba hai (fix size), `ArrayList` ek elastic bag hai — jitna dalo utna phailta hai.

### HashMap — Key-Value Pairs

```java
import java.util.HashMap;

HashMap<String, Double> meterReadings = new HashMap<>();
meterReadings.put("MTR-001", 245.5);
meterReadings.put("MTR-002", 189.2);

double reading = meterReadings.get("MTR-001");   // 245.5
boolean exists = meterReadings.containsKey("MTR-003");  // false

for (String key : meterReadings.keySet()) {
    System.out.println(key + " -> " + meterReadings.get(key));
}
```

> **Yaad Rakho:** `HashMap` me lookup `O(1)` (bahut fast) hota hai by key — isiliye "meter ID se reading dhoondo" jaise cases me `ArrayList` pe loop lagane se kahin better hai.

| Collection | Ordered? | Duplicates? | Best For |
|------------|----------|-------------|----------|
| `Array` | Yes | Yes | Fixed-size known data |
| `ArrayList` | Yes | Yes | Growing lists (RecyclerView data!) |
| `HashMap` | No | Keys unique | Fast key-based lookup |

## Block 3 — String + Exception Handling

### String Handling

```java
String name = "Smart Meter";
System.out.println(name.length());              // 11
System.out.println(name.toUpperCase());          // SMART METER
System.out.println(name.substring(0, 5));         // Smart
System.out.println(name.contains("Meter"));       // true
System.out.println(name.replace("Meter", "App")); // Smart App

// Concatenation
String meterId = "MTR-001";
String log = "Reading recorded for " + meterId + " at " + System.currentTimeMillis();
```

> **Tip:** Loop ke andar bahut saare `+` se String jodna slow hai (har baar naya String object banta hai — String **immutable** hoti hai). Loop me `StringBuilder` use karo:

```java
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 5; i++) {
    sb.append("Reading ").append(i).append("\n");
}
System.out.println(sb.toString());
```

### Exception Handling

```java
public double calculateUnits(double current, double previous) {
    try {
        if (previous > current) {
            throw new IllegalArgumentException("Previous reading zyada nahi ho sakti current se");
        }
        return current - previous;
    } catch (IllegalArgumentException e) {
        System.out.println("Error: " + e.getMessage());
        return 0;
    } finally {
        System.out.println("Calculation attempt complete");
    }
}
```

> **Socho Aise:** `try` = "ye risky kaam karo", `catch` = "agar galat hua to ye karo", `finally` = "chahe kuch bhi ho, ye zaroor chalega" (jaise network call ke baad loading spinner band karna).

> **Yaad Rakho:** Android me network/DB calls hamesha `try-catch` me hote hain — `NullPointerException`, `IOException`, `SQLException` common crashes hain jo isse rukte hain. Ye Day 4-6 me baar-baar aayega.

## Block 4 — Class, Object, Constructor

### 🧠 Theory: OOP Ki Zaroorat Kyun Padi

1990s se pehle "Procedural" programming chalti thi — poora program top-to-bottom functions ka collection hota tha, data aur uspe kaam karne wale functions **alag-alag** rehte the. Jaise-jaise programs bade hue, ek problem aayi:

> Agar 50 jagah `MeterReading` ka data use ho raha hai, aur uska structure badalna pade — 50 jagah dhoondh ke fix karna padta tha. Bugs badhte gaye, maintenance mushkil hoti gayi.

**OOP ka solution:** Data (`meterId`, `reading`) aur uspe kaam karne wale methods (`printReading()`) ko **ek hi unit (class)** me band kar do. Ab badlaav sirf ek jagah — class ke andar — hota hai.

> **Socho Aise:** Procedural programming ek khula bazaar hai — saaman (data) aur dukaanein (functions) alag-alag bikhri hain, koi bhi kisi bhi saaman ko chhed sakta hai. OOP ek dukaan hai jahan saaman shelf ke andar band hai (encapsulation) — sirf dukaan ke apne staff (methods) hi use handle karte hain.

Android me har `Activity`, `Fragment`, `ViewModel` — sab classes hain. OOP samjhe bina Android samajhna mushkil hoga — isiliye aaj poora din isi pe hai.

### Class = Blueprint, Object = Real Cheez

```java
public class MeterReading {
    // Fields (data)
    String meterId;
    double reading;
    long timestamp;

    // Constructor — object banate waqt chalta hai
    public MeterReading(String meterId, double reading, long timestamp) {
        this.meterId = meterId;
        this.reading = reading;
        this.timestamp = timestamp;
    }

    // Method (behavior)
    public void printReading() {
        System.out.println(meterId + ": " + reading + " units at " + timestamp);
    }
}

public class Main {
    public static void main(String[] args) {
        MeterReading r1 = new MeterReading("MTR-001", 245.5, System.currentTimeMillis());
        r1.printReading();   // MTR-001: 245.5 units at 1755...
    }
}
```

> **Yaad Rakho:** `class` sirf template hai — memory nahi leta jab tak `new` se object nahi banaya jaata. Har `new MeterReading(...)` ek naya, independent object banata hai.

### Constructor Overloading

```java
public class MeterReading {
    String meterId;
    double reading;

    // Constructor 1 — full data
    public MeterReading(String meterId, double reading) {
        this.meterId = meterId;
        this.reading = reading;
    }

    // Constructor 2 — default reading
    public MeterReading(String meterId) {
        this(meterId, 0.0);   // calls Constructor 1
    }
}
```

> **Tip:** Multiple constructors se ek hi class ko alag-alag tarike se initialize kar sakte ho — Android me ye `Model` classes banate waqt bahut kaam aata hai.

## Block 5 — Encapsulation, Inheritance, Polymorphism, Overloading vs Overriding

### Encapsulation — Data Ko Protect Karna

```java
public class MeterAccount {
    private double balance;   // private = bahar se direct access nahi

    public double getBalance() {
        return balance;
    }

    public void addRecharge(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }
}
```

> **Socho Aise:** `private` field = ATM ke andar ka cash — direct hath nahi laga sakte, sirf ATM machine (getter/setter methods) ke through interact karte ho. Isse galat values (jaise negative balance) set hone se rokte ho.

### Inheritance — Parent Se Child

```java
// Parent class
public class Device {
    String deviceId;
    public void showInfo() {
        System.out.println("Device: " + deviceId);
    }
}

// Child class
public class SmartMeter extends Device {
    double currentReading;
    public void showReading() {
        System.out.println("Reading: " + currentReading);
    }
}

// Usage
SmartMeter meter = new SmartMeter();
meter.deviceId = "MTR-001";       // inherited from Device
meter.currentReading = 245.5;
meter.showInfo();                  // inherited method
meter.showReading();               // own method
```

> **Yaad Rakho:** Java me sirf **single inheritance** allowed hai (`extends` ek hi class se). Multiple behavior chahiye to `interface` use karo (Block 6 me aayega).

### Polymorphism — Ek Naam, Alag Roop

```java
class Device {
    public void sync() {
        System.out.println("Generic sync");
    }
}

class SmartMeter extends Device {
    @Override
    public void sync() {
        System.out.println("Meter reading synced to server");
    }
}

// Runtime polymorphism
Device d = new SmartMeter();
d.sync();   // "Meter reading synced to server" — SmartMeter ka version chalta hai
```

> **Socho Aise:** `sync()` bolne pe kya hota hai — ye depend karta hai **actual object** kya hai, na ki variable ka declared type. Ye Android me `ViewModel`/`Repository` interfaces me bahut use hota hai.

### Overloading vs Overriding

```java
class Calculator {
    // OVERLOADING — same class, same name, different parameters
    int add(int a, int b) { return a + b; }
    double add(double a, double b) { return a + b; }
    int add(int a, int b, int c) { return a + b + c; }
}

class Parent {
    void greet() { System.out.println("Hello from Parent"); }
}
class Child extends Parent {
    // OVERRIDING — parent-child, same signature, new behavior
    @Override
    void greet() { System.out.println("Hello from Child"); }
}
```

| | Overloading | Overriding |
|---|---|---|
| Kahan | Same class | Parent-Child class |
| Signature | Different parameters | Exact same signature |
| Decide kab | Compile time | Runtime |
| Keyword | Koi nahi | `@Override` |

> **Interview Trap:** "Overloading compile-time polymorphism hai, overriding runtime polymorphism" — ye line bahut poochi jaati hai.

## Block 6 — Abstraction, Interface vs Abstract Class

### Abstraction — "Kya" Dikhao, "Kaise" Chhupao

```java
abstract class PaymentMethod {
    abstract void processPayment(double amount);   // no body — subclass implement karega

    void printReceipt() {   // normal method — sab subclasses use kar sakte hain
        System.out.println("Payment receipt generated");
    }
}

class CardPayment extends PaymentMethod {
    @Override
    void processPayment(double amount) {
        System.out.println("Processing card payment: ₹" + amount);
    }
}
```

> **Socho Aise:** Car chalate waqt tumhe pata hai steering ghumana hai aur accelerator dabana hai — engine ke andar kya ho raha hai (abstraction) tumhe pata karne ki zaroorat nahi.

### Interface — Pure Contract

```java
interface SyncListener {
    void onSyncSuccess();
    void onSyncFailed(String error);
}

class MeterRepository implements SyncListener {
    @Override
    public void onSyncSuccess() {
        System.out.println("Sync done!");
    }
    @Override
    public void onSyncFailed(String error) {
        System.out.println("Sync failed: " + error);
    }
}
```

### Interface vs Abstract Class

| | Abstract Class | Interface |
|---|---|---|
| Methods | Abstract + concrete dono | Sab abstract (Java 8+ me `default` bhi) |
| Fields | Kisi bhi type ke | Sirf `public static final` |
| Inheritance | Ek hi class `extends` kar sakti | Multiple `implements` kar sakti |
| Kab use karo | Common base behavior share karna ho | Sirf ek contract/capability define karna ho |

> **Yaad Rakho:** Android me `SyncListener`, `OnClickListener` jaise callbacks hamesha **interface** hote hain — kyunki ek class ek saath multiple interfaces implement kar sakti hai, lekin sirf ek class extend kar sakti hai.

## Block 7 — `this`, `super`, `static`, `final`

```java
class Device {
    String id;
    Device(String id) {
        this.id = id;          // "this" = current object ka field
    }
    void show() {
        System.out.println("Device ID: " + this.id);
    }
}

class SmartMeter extends Device {
    double reading;
    SmartMeter(String id, double reading) {
        super(id);              // "super" = parent constructor call
        this.reading = reading;
    }
    void show() {
        super.show();           // "super" = parent ka method call
        System.out.println("Reading: " + reading);
    }
}

class Config {
    static String appName = "MeterApp";       // "static" = class-level, sab objects me shared
    static final double TAX_RATE = 0.18;       // "final" = ek baar set, kabhi badal nahi sakta
}
```

| Keyword | Matlab |
|---------|--------|
| `this` | "Mera current object" — field/constructor confusion door karta hai |
| `super` | "Mera parent" — parent constructor ya method call karta hai |
| `static` | Class ki property, object ki nahi — sab instances me shared |
| `final` | Ek baar set, phir immutable (variable/method/class) |

> **Tip:** `static final` combo Android me constants ke liye standard hai: `public static final String BASE_URL = "https://api.example.com/";`

## Block 8 — Mini Project: Library Management System (30-45 min)

Sab OOP concepts ek chhoti console app me combine karo:

```java
import java.util.ArrayList;

// Abstraction + base class
abstract class LibraryItem {
    protected String title;   // "protected" — child class access kar sakti
    protected boolean isIssued;

    public LibraryItem(String title) {
        this.title = title;
        this.isIssued = false;
    }

    abstract String getCategory();   // subclass batayega ye kya cheez hai

    public void issue() {
        this.isIssued = true;
        System.out.println(title + " issued.");
    }
}

// Inheritance + Overriding
class Book extends LibraryItem {
    private String author;

    public Book(String title, String author) {
        super(title);
        this.author = author;
    }

    @Override
    String getCategory() {
        return "Book by " + author;
    }
}

class Magazine extends LibraryItem {
    private int issueNumber;

    public Magazine(String title, int issueNumber) {
        super(title);
        this.issueNumber = issueNumber;
    }

    @Override
    String getCategory() {
        return "Magazine issue #" + issueNumber;
    }
}

// Encapsulation
class Library {
    private ArrayList<LibraryItem> items = new ArrayList<>();

    public void addItem(LibraryItem item) {
        items.add(item);
    }

    public void showAll() {
        for (LibraryItem item : items) {
            System.out.println(item.title + " — " + item.getCategory() +
                    (item.isIssued ? " [ISSUED]" : " [AVAILABLE]"));
        }
    }
}

public class Main {
    public static void main(String[] args) {
        Library library = new Library();
        Book book1 = new Book("Clean Code", "Robert Martin");
        Magazine mag1 = new Magazine("Tech Today", 45);

        library.addItem(book1);
        library.addItem(mag1);

        book1.issue();   // polymorphic call — chalega Book/LibraryItem ke hisab se

        library.showAll();
    }
}
```

**Output:**
```
Clean Code issued.
Clean Code — Book by Robert Martin [ISSUED]
Tech Today — Magazine issue #45 [AVAILABLE]
```

> **Challenge:** Ek `DVD` class add karo (`extends LibraryItem`) apni `getCategory()` ke saath, aur `Library` me ek `issuedCount()` method add karo jo total issued items count kare.

### 🔬 Hands-On Lab: OOP Ko Todo, Fir Dekho Kya Hota Hai

Sirf padhna kaafi nahi — jaanbujh kar galtiyan karke dekho ki compiler kya bolta hai. In sabko try karo (online compiler pe ya terminal pe):

1. `abstract class LibraryItem` ka seedha `new LibraryItem("Test")` object banane ki koshish karo — compiler error dekho aur samjho kyun (abstract class ka direct instance nahi ban sakta).
2. `Book` class me `getCategory()` ke upar se `@Override` hata do — kya farak padta hai? (Kuch nahi, `@Override` optional hai, par compiler-check ke liye best practice hai — try karo isse hata ke ek typo daal do method name me, jaise `getCatgory()` — bina `@Override` ke ye silently naya method ban jaayega, error nahi aayega!)
3. `Library` class me `items` field ko `private` se `public` kar do, phir bahar se `library.items.clear()` chala do — socho real app me isse kya problem ho sakti hai (koi bhi bina check kiye poora data delete kar sakta hai).

> **Yaad Rakho:** Errors jaanbujh kar karke dekhna sabse fast tarika hai concepts pakka karne ka — production me ye mistakes crash ya security issues bante hain.

## 🎯 Interview Tips

1. **Q: Abstract class aur Interface me kab kaunsa use karoge?**
   *A: Common code share karna ho (base implementation) to abstract class; sirf capability/contract define karna ho aur multiple inheritance chahiye to interface.*

2. **Q: Overloading vs Overriding — one line me?**
   *A: Overloading compile-time (same class, different params), Overriding runtime (parent-child, same signature).*

3. **Q: `ArrayList` vs `Array`?**
   *A: Array fixed-size, ArrayList dynamic aur resizable — built-in helper methods (add/remove/contains) ke saath.*

4. **Q: `static` variable kab use karoge real app me?**
   *A: Jab value sab objects me common honi chahiye — jaise `BASE_URL`, constants, ya counters.*
