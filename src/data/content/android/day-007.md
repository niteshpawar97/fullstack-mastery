## Block 1 — Main Thread, Background Work, ANR, Memory Leak

### Main Thread (UI Thread)

Har Android app ka **ek Main Thread** hota hai jo UI draw karta hai, touch events handle karta hai, animations chalata hai. Isko kabhi block mat karo.

```java
// GALAT — Main thread pe heavy kaam
@Override
protected void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);
    List<MeterReadingEntity> data = dao.getAllReadings();   // Room crash karega yahan
    Thread.sleep(3000);   // ye bhi UI freeze karega
}
```

### ANR (Application Not Responding)

> **Yaad Rakho:** Agar Main Thread **5 seconds se zyada** block ho jaaye, Android system **ANR dialog** dikhata hai ("App isn't responding") — user ko "Wait" ya "Close" ka option milta hai. Ye sabse bura crash experience hai.

### Background Work — Kaise Karo

```java
// Executor se
ExecutorService executor = Executors.newSingleThreadExecutor();
executor.execute(() -> {
    List<MeterReadingEntity> data = dao.getAllReadings();   // background thread — safe
    runOnUiThread(() -> updateUI(data));                     // UI update wapas main thread pe
});
```

> **Socho Aise:** Main Thread ek akela reception counter hai jahan sab customers (touch events, drawing) line me lagte hain. Agar counter pe koi bahut lamba kaam (heavy computation) kar raha hai, poori line ruk jaati hai — customers frustrate ho jaate hain (ANR).

### Memory Leak

```java
// GALAT — Activity ka reference static field me rakh diya
public class MeterRepository {
    private static Activity activityRef;   // ye Activity ko kabhi garbage collect nahi hone dega

    public void setActivity(Activity activity) {
        activityRef = activity;   // MEMORY LEAK
    }
}
```

> **Warning:** Activity ka reference kisi **long-lived object** (static field, singleton, background thread) me rakhna memory leak ka sabse common karan hai — Activity destroy ho jaati hai par memory se free nahi hoti kyunki koi usse "pakde" hai.

> **Fix:** `WeakReference<Activity>` use karo, ya better — Activity reference bilkul mat pakdo, sirf `Context.getApplicationContext()` ya callback interfaces use karo.

## Block 2 — Notification + NotificationChannel + PendingIntent

### NotificationChannel (Android 8+ Ke Liye Zaroori)

```java
public void createNotificationChannel(Context context) {
    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
        NotificationChannel channel = new NotificationChannel(
                "sync_channel",
                "Sync Notifications",
                NotificationManager.IMPORTANCE_DEFAULT
        );
        channel.setDescription("Meter reading sync status updates");
        NotificationManager manager = context.getSystemService(NotificationManager.class);
        manager.createNotificationChannel(channel);
    }
}
```

> **Yaad Rakho:** Android 8.0 (API 26) ke baad har notification ek `NotificationChannel` se belong karti hai — bina channel ke notification dikhegi hi nahi. User channel-wise notifications on/off kar sakta hai (Settings me).

### PendingIntent — Notification Click Pe Kya Ho

```java
public void showSyncNotification(Context context, boolean success) {
    Intent intent = new Intent(context, DashboardActivity.class);
    PendingIntent pendingIntent = PendingIntent.getActivity(
            context, 0, intent,
            PendingIntent.FLAG_UPDATE_CURRENT | PendingIntent.FLAG_IMMUTABLE
    );

    NotificationCompat.Builder builder = new NotificationCompat.Builder(context, "sync_channel")
            .setSmallIcon(R.drawable.ic_sync)
            .setContentTitle(success ? "Sync Complete" : "Sync Failed")
            .setContentText(success ? "All readings synced successfully" : "Will retry automatically")
            .setPriority(NotificationCompat.PRIORITY_DEFAULT)
            .setContentIntent(pendingIntent)
            .setAutoCancel(true);

    NotificationManagerCompat.from(context).notify(1001, builder.build());
}
```

> **Socho Aise:** `PendingIntent` ek pre-filled, sealed lifafa hai jo **future me** (jab user notification pe tap kare) Android system khud "post" karega — abhi ke abhi execute nahi hota, "baad me chalane ka permission slip" hai.

## Block 3 — Service + Foreground Service

### Service — Bina UI Ke Background Kaam

```java
public class DataCleanupService extends Service {
    @Override
    public int onStartCommand(Intent intent, int flags, int startId) {
        // background me kaam karo (jaise old synced records delete karna)
        cleanupOldRecords();
        return START_NOT_STICKY;
    }

    @Override
    public IBinder onBind(Intent intent) {
        return null;   // bound service nahi hai
    }
}
```

### Foreground Service — Visible, Ongoing Kaam

```java
public class SyncForegroundService extends Service {
    @Override
    public int onStartCommand(Intent intent, int flags, int startId) {
        Notification notification = new NotificationCompat.Builder(this, "sync_channel")
                .setContentTitle("Syncing meter readings...")
                .setSmallIcon(R.drawable.ic_sync)
                .build();

        startForeground(1, notification);   // ongoing notification zaroori hai
        performSync();
        return START_NOT_STICKY;
    }
}
```

| | Service | Foreground Service |
|---|---|---|
| Notification | Optional | **Zaroori** — persistent notification dikhani padti hai |
| Priority | System kabhi bhi kill kar sakta hai (low memory) | High priority — system aasani se kill nahi karta |
| Use Case | Chhota, quick background kaam | Lamba, user-visible kaam (music playback, ongoing sync) |

> **Yaad Rakho:** Ye 7-day Smart Meter app me **WorkManager hi kaafi hai** background sync ke liye — `Foreground Service` sirf tab chahiye jab sync **lamba aur user ko dikhna zaroori** ho (jaise "syncing 500 readings...").

## Block 4 — Permissions + Runtime Permissions

### Manifest Me Declare Karo

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
```

### Runtime Permission Request (Android 6+)

```java
ActivityResultLauncher<String> permissionLauncher = registerForActivityResult(
        new ActivityResultContracts.RequestPermission(),
        isGranted -> {
            if (isGranted) {
                startSyncNotifications();
            } else {
                showPermissionDeniedMessage();
            }
        }
);

if (ContextCompat.checkSelfPermission(this, Manifest.permission.POST_NOTIFICATIONS)
        != PackageManager.PERMISSION_GRANTED) {
    permissionLauncher.launch(Manifest.permission.POST_NOTIFICATIONS);
} else {
    startSyncNotifications();
}
```

> **Socho Aise:** `INTERNET` jaisi "normal" permissions Manifest me likhte hi mil jaati hain — koi popup nahi. Par `Location`, `Camera`, `Notifications` (Android 13+) jaisi "dangerous" permissions ke liye **runtime pe user se explicitly poochna** padta hai — society me kisi ke flat me jaane se pehle unse poochna padta hai, gate pass (Manifest) kaafi nahi.

### Permission Denied Gracefully Handle Karna

```java
if (shouldShowRequestPermissionRationale(Manifest.permission.POST_NOTIFICATIONS)) {
    // user ne pehle deny kiya tha — samjhao kyun chahiye
    showRationaleDialog("Sync updates ke liye notification permission chahiye");
} else {
    // ya to pehli baar poochna hai, ya "Don't ask again" select kiya tha
    permissionLauncher.launch(Manifest.permission.POST_NOTIFICATIONS);
}
```

> **Warning:** Permission deny hone par app **crash nahi honi chahiye** — feature gracefully disable karo (e.g., notifications ke bina bhi sync silently chalta rahe), aur user ko clearly batao kya miss ho raha hai.

## Block 5 — Full MVVM Architecture: View, ViewModel, Repository, Model

```
Activity/Fragment (View)
        ↓  observes
    ViewModel
        ↓  calls
   Repository
      ↙   ↘
 Retrofit  Room
    ↓
  Server
```

### Model — Data Ka Shape

```java
public class MeterReading {
    public String meterId;
    public double reading;
    public long timestamp;
    public String syncStatus;
}
```

### Repository — Single Source of Truth

```java
public class MeterRepository {
    private final MeterApiService api;
    private final MeterReadingDao dao;

    public MeterRepository(Context context) {
        api = RetrofitClient.getInstance().create(MeterApiService.class);
        dao = AppDatabase.getInstance(context).meterReadingDao();
    }

    public LiveData<List<MeterReadingEntity>> getReadings(String meterId) {
        return dao.getReadingsForMeterLive(meterId);   // Room LiveData — DB change hote hi auto-update
    }

    public void saveReading(String meterId, double reading) {
        // Day 6 wala poora offline-first save+sync logic yahan
    }
}
```

### ViewModel — UI State Manage Karta Hai, Rotation Survive Karta Hai

```java
public class MeterViewModel extends ViewModel {
    private final MeterRepository repository;
    private final LiveData<List<MeterReadingEntity>> readings;

    public MeterViewModel(MeterRepository repository, String meterId) {
        this.repository = repository;
        this.readings = repository.getReadings(meterId);
    }

    public LiveData<List<MeterReadingEntity>> getReadings() {
        return readings;
    }

    public void saveReading(String meterId, double reading) {
        repository.saveReading(meterId, reading);
    }
}
```

### View (Activity/Fragment) — Sirf UI, Koi Business Logic Nahi

```java
public class DashboardActivity extends AppCompatActivity {
    private MeterViewModel viewModel;
    private ActivityDashboardBinding binding;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        binding = ActivityDashboardBinding.inflate(getLayoutInflater());
        setContentView(binding.getRoot());

        MeterRepository repository = new MeterRepository(getApplicationContext());
        viewModel = new ViewModelProvider(this, new MeterViewModelFactory(repository, "MTR-001"))
                .get(MeterViewModel.class);

        MeterReadingAdapter adapter = new MeterReadingAdapter();
        binding.recyclerView.setAdapter(adapter);

        // LiveData observe — Room me data badalte hi UI auto-update, koi manual refresh nahi
        viewModel.getReadings().observe(this, readings -> adapter.submitList(readings));

        binding.btnSaveReading.setOnClickListener(v -> {
            double reading = Double.parseDouble(binding.etReading.getText().toString());
            viewModel.saveReading("MTR-001", reading);
        });
    }
}
```

> **Yaad Rakho:** `ViewModel` **screen rotation survive karta hai** — Activity destroy/recreate hoti hai par ViewModel zinda rehta hai, isliye data dobara load karne ki zaroorat nahi padti.

> **Socho Aise:** MVVM ek restaurant hai — **View** (Activity) waiter hai jo sirf order leta/serve karta hai, kabhi khud khaana nahi banata. **ViewModel** manager hai jo order coordinate karta hai. **Repository** kitchen ka in-charge hai jo decide karta hai fridge (Room) se lena hai ya market (Retrofit) se mangwana hai. **Model** khud khaana (data) hai.

> **Tip:** Android Studio ke Logcat me tag se filter karo (`tag:SyncWorker`) — poore app ke logs me se sirf relevant cheez dhoondhna aasan ho jaata hai.

### Postman — API Ko App Se Alag Test Karna

Backend team ne API di — pehle **Postman me test karo** (headers, body, response) taaki pata chale problem app ke code me hai ya API me.

```
POST https://api.smartmeter.com/auth/login
Headers: Content-Type: application/json
Body: { "email": "test@app.com", "password": "test123" }
```

> **Socho Aise:** Postman ek "practice ground" hai — Retrofit code likhne se pehle API manually test kar lo, taaki debug karte waqt confusion na ho ki bug app ke Java code me hai ya server side pe.

### API Debugging — Common Issues

| Symptom | Likely Cause |
|---------|--------------|
| `401 Unauthorized` | Token missing/expired — Interceptor check karo |
| `NullPointerException` on response | `@SerializedName` field name mismatch |
| Timeout | Server slow, ya OkHttp timeout kam set hai |
| Data Postman me sahi, app me galat | JSON model class me field naming galat |

> **Tip:** OkHttp `LoggingInterceptor` (Day 4) hamesha ON rakho debug builds me — exact request/response dikhta hai Logcat me, isse 80% API bugs khud pakड़ jaate hain.

### APK vs AAB

| | APK | AAB (Android App Bundle) |
|---|---|---|
| Kya Hai | Directly installable file | Play Store ke liye publishing format |
| Size | Poora — saare device configs (screen density, CPU arch) ek file me | Play Store khud split karta hai — user ko sirf uske device ke liye chahiye utna download hota hai |
| Use | Direct install/testing, sideloading | Play Store submission (2021 se **mandatory**) |

> **Yaad Rakho:** Local testing ke liye APK banao (`Build > Build APK`). Play Store pe publish karne ke liye AAB banao (`Build > Build Bundle`) — Play Store isse device-specific optimized APK khud generate karta hai, jisse user ka download size kam hota hai.

## Block 8 — Mock Interview: Project Questions, Coding Questions, Full Wiring

### Project-Based Questions (Apna Smart Meter Project Explain Karo)

1. **"Apne project ki architecture batao."**
   *Answer structure: "Maine MVVM + Repository pattern use kiya. View sirf UI render karta hai aur ViewModel ko observe karta hai. ViewModel Repository ko call karta hai. Repository decide karta hai — Room se turant data do (offline-first), aur background me Retrofit se fresh data la kar Room update karo."*

2. **"Offline mode kaise kaam karta hai tumhare app me?"**
   *"Room hamesha source of truth hai. User jab reading save karta hai, wo turant Room me PENDING status ke saath save hoti hai — UI turant reflect karta hai. Agar internet hai to turant sync try hota hai, nahi to WorkManager schedule ho jaata hai jo internet aane pe automatically sync karega."*

3. **"Duplicate data kaise prevent kiya?"**
   *"Har reading ke saath ek client-generated UUID (`clientUuid`) bhejta hoon. Agar response network me kho bhi jaaye aur app retry kare, server usi UUID ko dekh ke samajh jaata hai ki ye already process ho chuka hai — duplicate record nahi banta."*

4. **"WorkManager kyun use kiya, simple background thread kyun nahi?"**
   *"Kyunki WorkManager guaranteed execution deta hai — app close ho jaaye ya phone restart ho jaaye, scheduled sync abhi bhi hoga jab constraints (internet) satisfy ho. Simple thread app process ke saath hi mar jaata.*"

```java
public int countPending(List<MeterReadingEntity> readings) {
    int count = 0;
    for (MeterReadingEntity r : readings) {
        if (SyncStatus.PENDING.equals(r.syncStatus)) {
            count++;
        }
    }
    return count;
}
```

**Q: Reverse a String without using built-in reverse methods.**

```java
public String reverse(String input) {
    char[] chars = input.toCharArray();
    int left = 0, right = chars.length - 1;
    while (left < right) {
        char temp = chars[left];
        chars[left] = chars[right];
        chars[right] = temp;
        left++;
        right--;
    }
    return new String(chars);
}
```

## 🎯 Final Interview Tips

1. **Q: Kis wajah se MVVM chuna, MVC ya MVP nahi?**
   *A: MVVM me View aur ViewModel ke beech LiveData/data-binding ka loose coupling hota hai — ViewModel ko View ka reference bilkul nahi chahiye, isse testing aasan hota hai aur lifecycle-aware observers memory leaks kam karte hain.*

2. **Q: Repository pattern ka real fayda kya hai?**
   *A: ViewModel/UI ko pata hi nahi hona chahiye data Room se aa raha hai ya Retrofit se — Repository ye decision khud leta hai. Kal agar data source badle (naya caching layer, GraphQL), sirf Repository badalna padega, UI code nahi.*

3. **Q: Apne app me RecyclerView performance kaise maintain ki?**
   *A: ViewHolder pattern se `findViewById` repeat nahi kiya, `onBindViewHolder` me heavy work avoid kiya, aur list updates ke liye `notifyItemInserted`/`DiffUtil` use kiya poori list refresh karne ke bajaye.*

4. **Q: Agar API call fail ho jaaye to app kaise react karta hai?**
   *A: `onFailure()` me network errors (timeout, no internet) catch karke reading ko FAILED status me Room me rakhte hain — WorkManager ka retry mechanism use karke automatically dobara try hota hai jab internet wapas aata hai.*
