# Bonus Day 9: PHP + MySQL Backend — Smart Meter API

> **Ye din kyun:** Day 8 me poora Android app bana, par wo `api.smartmeter.com` ko call karta hai — jo **exist hi nahi karta**. Aaj hum ek **real, chalne wala backend** banayenge PHP + MySQL se, jo exactly wahi endpoints deta hai jo Android app expect karta hai. Ban jaane ke baad, poora project — Android app + real backend + real database — **end-to-end chalega**.
>
> PHP + MySQL isliye chuna kyunki dono deploy karna aasan hai (koi bhi shared hosting — Hostinger, cPanel — PHP+MySQL out-of-the-box support karta hai, alag se server setup nahi chahiye), aur syntax seekhna beginner ke liye seedha hai.

---

## Step 0: Local Setup

1. [XAMPP](https://www.apachefriends.org) download karo (Windows/Mac/Linux) — isme Apache (server), PHP, aur MySQL teeno saath aate hain.
2. Install karke **XAMPP Control Panel** kholo, **Apache** aur **MySQL** dono **Start** karo.
3. Browser me `http://localhost/phpmyadmin` kholo — ye MySQL ka visual database manager hai.
4. XAMPP ke `htdocs` folder ke andar ek naya folder banao: `smartmeter-api/`

> **Yaad Rakho:** `htdocs` folder Apache ka "public root" hai — jo bhi isme rakhoge, `http://localhost/foldername/file.php` se accessible hoga. Ye bilkul waisa hi hai jaise Android me `res/` folder resources ke liye reserved hai.

## Step 1: MySQL Database Schema

phpMyAdmin me **New** database banao naam `smartmeter`, phir **SQL** tab me ye query chalao:

```sql
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL
);

CREATE TABLE meter_readings (
    id INT AUTO_INCREMENT PRIMARY KEY,
    client_uuid VARCHAR(36) UNIQUE NOT NULL,
    meter_id VARCHAR(50) NOT NULL,
    reading DOUBLE NOT NULL,
    timestamp BIGINT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 🧠 Theory: Ye Schema Android Ke Concepts Se Seedha Judta Hai

| SQL Design Choice | Android Concept (kaunse din) |
|---|---|
| `client_uuid VARCHAR(36) UNIQUE` | Duplicate Prevention (Day 6) — DB khud hi doosri baar same UUID insert nahi hone dega |
| `password_hash`, plain `password` nahi | Password Hashing Theory (Day 5) — kabhi bhi real password store nahi karte |
| `timestamp BIGINT` (epoch millis), `DATETIME` nahi | Timestamp Theory (Day 6) — Android bhi `long` (epoch millis) use karta hai, dono taraf format match hona chahiye |

> **Socho Aise:** `client_uuid UNIQUE` constraint database ka apna "bouncer" hai — chahe app kitni bhi baar wahi UUID bheje (network retry ki wajah se), database khud hi doosri entry reject/ignore kar dega. Ye Day 6 ka duplicate-prevention concept ab **server side** pe bhi lag raha hai — do-taraf ka protection.

### Ek Test User Banao

Agar upar wala hash apne se generate karna hai: `php -r "echo password_hash('test123', PASSWORD_DEFAULT);"` terminal me chalao.

Naye users ke liye ye tareeka error-prone hai (hash galat copy ho sakta hai — jo exact yahi issue tha jab tak fix nahi hua). **Step 5 me `register.php`** banayenge jo ye poora kaam khud, sahi tarike se karta hai — usके baad manual INSERT ki zaroorat hi nahi padegi.

## Step 2: Project Structure + DB Connection

`smartmeter-api/` ke andar ye files banao:

```
smartmeter-api/
├── config.php        (DB connection)
├── jwt_helper.php     (JWT generate/verify)
├── login.php
├── register.php
├── get_readings.php
└── submit_reading.php
```

**`config.php`**:
```php
<?php
header('Content-Type: application/json');
header('Access-Control-Allow-Origin: *');

$host = 'localhost';
$db   = 'smartmeter';
$user = 'root';
$pass = '';

try {
    $pdo = new PDO("mysql:host=$host;dbname=$db;charset=utf8mb4", $user, $pass);
    $pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
} catch (PDOException $e) {
    http_response_code(500);
    echo json_encode(['error' => 'Database connection failed']);
    exit;
}
```

### 🧠 Theory: PDO Kyun, Purana `mysqli` Kyun Nahi

**PDO (PHP Data Objects)** database queries me variables safely daalne ka tarika deta hai — **prepared statements** ke through.

```php
// GALAT — SQL Injection ka darwaza khula
$email = $_POST['email'];
$pdo->query("SELECT * FROM users WHERE email = '$email'");
// Agar koi email field me likh de: ' OR '1'='1
// Query ban jaati hai: SELECT * FROM users WHERE email = '' OR '1'='1'
// — sab users match ho jaayenge, security poori tarah toot gayi!

// SAHI — Prepared statement
$stmt = $pdo->prepare("SELECT * FROM users WHERE email = ?");
$stmt->execute([$email]);
// Yahan '?' sirf ek VALUE hai, kabhi bhi SQL command ki tarah execute nahi hoga
```

> **Yaad Rakho:** Jahan bhi user-input (email, password, kisi bhi form field) seedha SQL query me jaata hai, hamesha `?` placeholder + `execute([$value])` use karo — kabhi bhi string concatenation (`"...$variable..."`) se query mat banao.

> **CORS Note:** `Access-Control-Allow-Origin: *` header sirf **browser-based** clients (JavaScript fetch/XHR) ke liye zaroori hota hai. Android ka OkHttp/Retrofit native HTTP client hai — usko CORS ki zaroorat nahi. Ye header yahan future-proofing ke liye hai (agar kabhi web dashboard bhi banao).

## Step 3: JWT Helper — Manual Implementation

Production me tum [firebase/php-jwt](https://github.com/firebase/php-jwt) library (Composer se) use karoge — par **seekhne ke liye**, JWT manually banate hain taaki Day 5 ka "Header.Payload.Signature" theory **apni aankhon se PHP code me dikhe**.

**`jwt_helper.php`**:
```php
<?php
$secretKey = "smart-meter-secret-change-this-in-production";

function base64UrlEncode($data) {
    return rtrim(strtr(base64_encode($data), '+/', '-_'), '=');
}

function base64UrlDecode($data) {
    return base64_decode(strtr($data, '-_', '+/'));
}

function generateJWT($payload) {
    global $secretKey;
    $header = base64UrlEncode(json_encode(['alg' => 'HS256', 'typ' => 'JWT']));
    $payloadEncoded = base64UrlEncode(json_encode($payload));
    $signature = hash_hmac('sha256', "$header.$payloadEncoded", $secretKey, true);
    $signatureEncoded = base64UrlEncode($signature);
    return "$header.$payloadEncoded.$signatureEncoded";
}

function verifyJWT($token) {
    global $secretKey;
    $parts = explode('.', $token);
    if (count($parts) !== 3) return false;

    [$header, $payload, $signature] = $parts;
    $expectedSig = base64UrlEncode(hash_hmac('sha256', "$header.$payload", $secretKey, true));

    if (!hash_equals($expectedSig, $signature)) return false; // tamper check

    $payloadData = json_decode(base64UrlDecode($payload), true);
    if ($payloadData['exp'] < (time() * 1000)) return false; // expiry check

    return $payloadData;
}
```

> **Socho Aise:** Ye 3 lines — `$header.$payloadEncoded.$signatureEncoded` — **exact wahi** teen tukड़े hain jo Day 5 me padhe the (`Header.Payload.Signature`). `hash_hmac()` wahi "signing" hai jo secret key ke bina koi fake nahi bana sakta — koi bhi payload badal ke bheje, `$expectedSig` match nahi karega.

> **Warning:** `hash_equals()` use karo, seedha `==` nahi — `hash_equals()` **timing-safe comparison** karta hai (constant time), taaki koi attacker response-time measure karke signature guess na kar sake. Ye ek real security best practice hai.

## Step 4: Login Endpoint — `login.php`

Matches Android's `AuthApiService.login()` — same request/response shape.

```php
<?php
require 'config.php';
require 'jwt_helper.php';

$data = json_decode(file_get_contents('php://input'), true);
$email = $data['email'] ?? '';
$password = $data['password'] ?? '';

$stmt = $pdo->prepare("SELECT * FROM users WHERE email = ?");
$stmt->execute([$email]);
$user = $stmt->fetch();

if (!$user || !password_verify($password, $user['password_hash'])) {
    http_response_code(401);
    echo json_encode(['error' => 'Invalid credentials']);
    exit;
}

$expiresAt = (time() + 3600) * 1000; // 1 hour se expire, millis me (Android 'long' se match)
$token = generateJWT(['userId' => $user['id'], 'exp' => $expiresAt]);

echo json_encode(['token' => $token, 'expiresAt' => $expiresAt]);
```

> **Yaad Rakho:** `password_verify($password, $user['password_hash'])` — ye function plain password ko dobara hash karke stored hash se compare karta hai (Day 5 ka bcrypt theory). Kabhi bhi `$password === $user['password']` jaisa direct compare mat karo — password kabhi plain store hi nahi hota.

**Response** (exactly `LoginResponse.java` ke shape jaisa):
```json
{ "token": "eyJhbGc...", "expiresAt": 1755766800000 }
```

## Step 5: Register Endpoint — `register.php`

Ab tak naya user banane ke liye phpMyAdmin me manually bcrypt hash copy-paste karna pad raha tha — error-prone, aur ek galat character se poora login silently fail ho jaata hai (bina kisi clear error ke, kyunki hash bhi ek valid-dikhne wali string hi hoti hai). `register.php` ye poora kaam **PHP ke andar hi**, sahi tarike se karta hai — ab kabhi hash haath se likhne ki zaroorat nahi.

```php
<?php
require 'config.php';

$data = json_decode(file_get_contents('php://input'), true);
$email = $data['email'] ?? '';
$password = $data['password'] ?? '';

if (empty($email) || empty($password)) {
    http_response_code(400);
    echo json_encode(['error' => 'Email and password required']);
    exit;
}

if (strlen($password) < 6) {
    http_response_code(400);
    echo json_encode(['error' => 'Password must be at least 6 characters']);
    exit;
}

$check = $pdo->prepare("SELECT id FROM users WHERE email = ?");
$check->execute([$email]);
if ($check->fetch()) {
    http_response_code(409);
    echo json_encode(['error' => 'Email already registered']);
    exit;
}

$passwordHash = password_hash($password, PASSWORD_DEFAULT);
$stmt = $pdo->prepare("INSERT INTO users (email, password_hash) VALUES (?, ?)");
$stmt->execute([$email, $passwordHash]);

http_response_code(201);
echo json_encode(['message' => 'User registered successfully']);
```

> **Yaad Rakho:** `password_hash($password, PASSWORD_DEFAULT)` khud hi random salt generate karta hai aur usko hash ke andar hi embed kar deta hai — isiliye same password har baar **alag** hash deta hai, par `password_verify()` dono ko sahi se match karta hai (Day 5 ka theory, ab is guide ke apne bug se real-world proof mil gaya).

> **Socho Aise:** `SELECT id FROM users WHERE email = ?` se pehle check karna — phir insert — ye **"check-then-act"** pattern hai. `UNIQUE` constraint database level pe bhi ye rok deta agar do requests **exact same milisecond** pe aa jaayen (race condition), isliye do-taraf ka protection hai — bilkul Day 6 ke `client_uuid UNIQUE` jaisa hi soch.

**HTTP Status Codes yahan matter karte hain:**

| Status | Kab | Kyun ye code |
|---|---|---|
| `201 Created` | Naya user successfully ban gaya | REST convention — resource create hua |
| `400 Bad Request` | Email/password missing ya password chhota | Client ki galti — request hi invalid thi |
| `409 Conflict` | Email pehle se registered | Resource already exist karta hai — clash |

**Test Postman/curl se:**
```
POST http://localhost/smartmeter-api/register.php
Body: { "email": "newuser@app.com", "password": "mypassword" }
→ 201: { "message": "User registered successfully" }

POST (same email dobara)
→ 409: { "error": "Email already registered" }

POST http://localhost/smartmeter-api/login.php
Body: { "email": "newuser@app.com", "password": "mypassword" }
→ 200: { "token": "...", "expiresAt": ... }
```

## Step 6: Get Readings — `get_readings.php`

Matches `MeterApiService.getReadings(meterId, limit)` — GET with query params + JWT check.

```php
<?php
require 'config.php';
require 'jwt_helper.php';

// JWT check — Interceptor jo Android side pe header add karta hai, yahan verify hota hai
$headers = getallheaders();
$authHeader = $headers['Authorization'] ?? '';
$token = str_replace('Bearer ', '', $authHeader);
$payload = verifyJWT($token);

if (!$payload) {
    http_response_code(401);
    echo json_encode(['error' => 'Unauthorized']);
    exit;
}

$meterId = $_GET['meterId'] ?? '';
$limit = (int)($_GET['limit'] ?? 20);

$stmt = $pdo->prepare("SELECT meter_id AS meterId, reading, timestamp FROM meter_readings WHERE meter_id = ? ORDER BY timestamp DESC LIMIT ?");
$stmt->bindValue(1, $meterId);
$stmt->bindValue(2, $limit, PDO::PARAM_INT);
$stmt->execute();

echo json_encode($stmt->fetchAll(PDO::FETCH_ASSOC));
```

> **Yaad Rakho:** `AS meterId` — MySQL column `meter_id` (snake_case) ko `meterId` (camelCase) me alias kiya, taaki JSON response Android ke `MeterReadingResponse.java` field names se **exactly match** kare, bina Gson `@SerializedName` annotation ki zaroorat ke. Chhota trick, bahut kaam ka.

## Step 7: Submit Reading — `submit_reading.php`

Matches `MeterApiService.submitReading()` — POST, JWT check, **aur duplicate prevention** (Day 6).

```php
<?php
require 'config.php';
require 'jwt_helper.php';

$headers = getallheaders();
$token = str_replace('Bearer ', '', $headers['Authorization'] ?? '');
if (!verifyJWT($token)) {
    http_response_code(401);
    echo json_encode(['error' => 'Unauthorized']);
    exit;
}

$data = json_decode(file_get_contents('php://input'), true);

// Duplicate check — Day 6 ka clientUuid idempotency concept, ab DB pe
$check = $pdo->prepare("SELECT * FROM meter_readings WHERE client_uuid = ?");
$check->execute([$data['clientUuid']]);
$existing = $check->fetch();

if ($existing) {
    // Already processed — same record wapas bhejo, dobara insert mat karo
    echo json_encode([
        'meterId' => $existing['meter_id'],
        'reading' => (float)$existing['reading'],
        'timestamp' => (int)$existing['timestamp']
    ]);
    exit;
}

$stmt = $pdo->prepare("INSERT INTO meter_readings (client_uuid, meter_id, reading, timestamp) VALUES (?, ?, ?, ?)");
$stmt->execute([$data['clientUuid'], $data['meterId'], $data['reading'], $data['timestamp']]);

echo json_encode(['meterId' => $data['meterId'], 'reading' => $data['reading'], 'timestamp' => $data['timestamp']]);
```

> **Interview Trap:** Ye exact wahi scenario hai jo Day 6 me theory me padha tha — "response network me kho jaaye, app retry kare, server pe duplicate ban jaaye." Yahan `client_uuid UNIQUE` column + ye pehle-check-karo logic dono milke ye guarantee dete hain ki chahe request 5 baar bhi aaye, database me **sirf ek** record banega.

## Step 9: Android App Ko Is Local Backend Se Jodo

Day 8 ke `RetrofitClient.java` me `BASE_URL` badlo:

```java
// Emulator se localhost tak pahunchne ka special IP — "localhost" seedha kaam nahi karega
private static final String BASE_URL = "http://10.0.2.2/smartmeter-api/";
```

> **Yaad Rakho:** Android **emulator** apne aap ko `localhost`/`127.0.0.1` bolta hai — jo tumhare laptop ke localhost se **alag** hai (emulator ek virtual machine hai). `10.0.2.2` ek special address hai jo emulator **host machine (tumhara laptop) ke localhost** tak route karta hai.

> **Real Device Pe Test Karna Ho To:** Laptop aur phone dono **same Wi-Fi** pe hone chahiye, aur `BASE_URL` me `10.0.2.2` ki jagah laptop ka actual local IP (jaise `192.168.1.5`) use karo — Windows me `ipconfig` se pata chalega.

Aur Android Manifest me local (non-HTTPS) traffic allow karna padega (`cleartext traffic`), kyunki XAMPP by default plain HTTP pe chalta hai:

```xml
<application
    android:usesCleartextTraffic="true"
    ... >
```

> **Warning:** `usesCleartextTraffic="true"` sirf **local development** ke liye hai. Real production app hamesha HTTPS backend use kare — cleartext (plain HTTP) production me security risk hai (data bina encryption ke jaata hai).

## 📋 Quick Revision

| Concept | One-liner | Android Side Se Kaise Judta Hai |
|---------|-----------|-----------------------------------|
| PDO + Prepared Statements | `?` placeholder se SQL injection rokna | Same principle jo Room ke `@Query` compile-time checks deta hai |
| `password_hash()` / `password_verify()` | PHP ka built-in bcrypt hashing | Day 5 ka "password kabhi plain store nahi hota" theory |
| `register.php` | Naya user banata hai, khud hash generate karta hai | Manual hash copy-paste ki jagah — error ki gunjaish khatam |
| Manual JWT (Header.Payload.Signature) | `hash_hmac()` se sign karna | Day 5 me jo JWT padha, wahi structure yahan bana |
| `client_uuid UNIQUE` | DB-level duplicate prevention | Day 6 ka idempotency-key concept, ab server pe bhi |
| `10.0.2.2` | Emulator → laptop localhost route | Android emulator networking gotcha |
| `usesCleartextTraffic` | Local HTTP allow karna (dev only) | Production me hamesha HTTPS |

## 🎯 Interview Tips

1. **Q: Frontend (Android) aur backend (PHP) ke beech contract kaise maintain karte ho?**
   *A: Response field names ko dono taraf match karke — jaise SQL `AS meterId` alias, taaki Android ka Gson model bina extra annotation ke directly map ho jaaye.*

2. **Q: Duplicate submission kaise prevent hoti hai poore system me?**
   *A: Client (Android) ek UUID generate karta hai per-reading, server us UUID ko UNIQUE column me check karta hai — do-taraf ka protection, na Android retry se duplicate banega, na kisi aur client se same request aane se.*

3. **Q: JWT ko manually implement kiya — production me kya badlega?**
   *A: Production me `firebase/php-jwt` jaisi tested library use karoge (edge cases, algorithm confusion attacks jaise cheezein already handled hain) — manual implementation sirf concept samajhne ke liye tha.*

**Poora Android with Java track yahan complete hota hai** — 9 din me Java basics se lekar ek real, full-stack, end-to-end chalne wale system tak.
