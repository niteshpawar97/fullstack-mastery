## Block 1 — Android Project Structure + AndroidManifest

### Naya Project Banao

Android Studio → **New Project** → **Empty Views Activity** → Language: **Java** → Finish.

### Project Structure Samjho

```
app/
├── manifests/
│   └── AndroidManifest.xml     ← app ka "ID card"
├── java/com.example.app/
│   ├── MainActivity.java        ← tumhara Java code
├── res/
│   ├── layout/
│   │   └── activity_main.xml    ← UI screens (XML)
│   ├── drawable/                ← images, icons
│   ├── values/
│   │   ├── strings.xml          ← saare text yahan
│   │   ├── colors.xml           ← saare colors yahan
│   │   └── themes.xml           ← app ka theme
├── build.gradle (app level)     ← dependencies + app config
```

| Folder | Kya Hai |
|--------|---------|
| `java/` | Tumhara actual Java code — Activities, Adapters, Models |
| `res/layout/` | XML files jo screens define karte hain |
| `res/values/strings.xml` | Hardcoded text yahan nahi, `strings.xml` me rakho |
| `AndroidManifest.xml` | App ke saare components, permissions, entry point declare karta hai |

> **Yaad Rakho:** Text seedha XML me `android:text="Hello"` likhna bura practice hai — `strings.xml` me define karo aur `@string/hello` se refer karo. Translation aur maintenance dono aasan ho jaate hain.

### AndroidManifest.xml

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android">

    <uses-permission android:name="android.permission.INTERNET" />

    <application
        android:allowBackup="true"
        android:icon="@mipmap/ic_launcher"
        android:label="@string/app_name"
        android:theme="@style/Theme.MeterApp">

        <activity
            android:name=".MainActivity"
            android:exported="true">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>

        <activity android:name=".DashboardActivity" android:exported="false" />

    </application>
</manifest>
```

> **Socho Aise:** `AndroidManifest.xml` app ka "Aadhaar card" hai — OS ise sabse pehle padhta hai taaki jaan sake app ke paas kaunse screens hain, kaunsi permissions chahiye, aur kaun sa screen sabse pehle khulega (`MAIN` + `LAUNCHER`).

> **Warning:** Har `Activity` jo tum banate ho, use Manifest me register karna **zaroori** hai — warna `ActivityNotFoundException` crash milega.

## Block 2 — Activity + Activity Lifecycle

### Activity Kya Hai

`Activity` ek Java class hai jo **ek screen** represent karti hai. Har screen (Login, Dashboard, Settings) apni alag `Activity` class hoti hai.

```java
public class MainActivity extends AppCompatActivity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);   // XML layout connect karo
    }
}
```

> **Yaad Rakho:** `setContentView(R.layout.activity_main)` wahi line hai jo Java class ko XML UI se jodti hai. Isके bina screen khaali dikhega.

### Activity Lifecycle — 6 Callbacks

```java
public class MainActivity extends AppCompatActivity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);
        Log.d("Lifecycle", "onCreate — screen bani");
    }
    @Override
    protected void onStart() {
        super.onStart();
        Log.d("Lifecycle", "onStart — screen visible ho rahi hai");
    }
    @Override
    protected void onResume() {
        super.onResume();
        Log.d("Lifecycle", "onResume — user interact kar sakta hai ab");
    }
    @Override
    protected void onPause() {
        super.onPause();
        Log.d("Lifecycle", "onPause — dusri activity aane wali hai");
    }
    @Override
    protected void onStop() {
        super.onStop();
        Log.d("Lifecycle", "onStop — screen fully hidden");
    }
    @Override
    protected void onDestroy() {
        super.onDestroy();
        Log.d("Lifecycle", "onDestroy — activity khatam");
    }
}
```

> **Socho Aise:** Activity lifecycle bilkul ek TV show jaisa hai — `onCreate` = set banna, `onStart` = camera on, `onResume` = LIVE recording, `onPause` = ad-break (still set pe ho par recording nahi), `onStop` = studio khaali (kisi aur set pe chale gaye), `onDestroy` = shoot wrap.

| Callback | Kab Chalta Hai | Common Use |
|----------|----------------|------------|
| `onCreate()` | Activity pehli baar banti hai | Layout set karna, views init karna |
| `onStart()` | Screen visible hone lagi | — |
| `onResume()` | Screen fully interactive | Sensors/camera start karna |
| `onPause()` | Doosri activity upar aa rahi | Video pause, animation stop |
| `onStop()` | Screen fully hidden | Heavy resources release karna |
| `onDestroy()` | Activity destroy ho rahi | Final cleanup |

> **Tip:** `onCreate()` sirf **ek baar** chalta hai jab activity banti hai. Screen ko baar-baar visible/hidden hone pe `onStart()`/`onStop()` cycle chalta hai — `onCreate()` nahi.

## Block 3 — Activity A → B Lifecycle

Jab **Activity A** se **Activity B** open karte ho, callbacks ek fix order me chalte hain — ye interview me **bahut** poocha jaata hai.

```
User A open karta hai:
  A: onCreate → onStart → onResume

User A se B pe navigate karta hai (A.startActivity(B)):
  A: onPause
  B: onCreate → onStart → onResume
  A: onStop                          ← A ab poori tarah hidden hai

User Back button dabata hai (B se A pe wapas):
  B: onPause
  A: onRestart → onStart → onResume
  B: onStop → onDestroy              ← B destroy ho jaati hai
```

> **Yaad Rakho:** `A.onPause()` **pehle** chalta hai, `B.onResume()` ke **baad** — matlab thodi der ke liye **A paused** aur **B resumed** dono saath exist karte hain (jaise transparent dialog dikhane pe).

> **Interview Trap:** "Activity B pura resume hone tak Activity A ka `onStop()` nahi chalta" — ye exact sequence samajhna zaroori hai, kyunki isi wajah se `onPause()` me heavy kaam nahi karna chahiye (UI thread block ho sakti hai aur B ka open hona delay hoga).

## Block 4 — Intent: Explicit, Implicit, Extras

### Intent Kya Hai

`Intent` ek message/request object hai jo batata hai "kya karna hai" — naya screen kholna ho, ya kisi doosri app ko call karna ho.

### Explicit Intent — Apni App Ke Andar Specific Screen

```java
Intent intent = new Intent(MainActivity.this, DashboardActivity.class);
startActivity(intent);
```

> **Socho Aise:** Explicit Intent = kisi ko naam le kar bulana ("Raj, idhar aao") — exact pata hai kis activity ko kholna hai.

### Implicit Intent — System Ko Bologe "Ye Kaam Kar Do"

```java
// Browser kholna
Intent browserIntent = new Intent(Intent.ACTION_VIEW, Uri.parse("https://example.com"));
startActivity(browserIntent);

// Phone call
Intent callIntent = new Intent(Intent.ACTION_DIAL, Uri.parse("tel:9999999999"));
startActivity(callIntent);

// Share
Intent shareIntent = new Intent(Intent.ACTION_SEND);
shareIntent.setType("text/plain");
shareIntent.putExtra(Intent.EXTRA_TEXT, "Meter reading: 245.5 units");
startActivity(Intent.createChooser(shareIntent, "Share via"));
```

> **Socho Aise:** Implicit Intent = bhीड me chillaana ("Koi bhi jo browser khol sakta hai, please khol do") — Android system decide karta hai kaunsi app handle karegi (agar multiple apps ho to chooser dikhega).

### Intent Extras — Data Bhejna

```java
// A Activity se bhejna
Intent intent = new Intent(MainActivity.this, DashboardActivity.class);
intent.putExtra("USER_NAME", "Ashutosh");
intent.putExtra("METER_ID", "MTR-001");
intent.putExtra("CURRENT_READING", 245.5);
startActivity(intent);

// B Activity me receive karna
String userName = getIntent().getStringExtra("USER_NAME");
String meterId = getIntent().getStringExtra("METER_ID");
double reading = getIntent().getDoubleExtra("CURRENT_READING", 0.0);   // default value zaroori
```

> **Yaad Rakho:** `getDoubleExtra("KEY", defaultValue)` — dusra parameter **default value** hai agar key exist nahi karti. Isse `NullPointerException` se bacha jaata hai.

| Intent Type | Use Case |
|-------------|----------|
| Explicit | Apni app ke andar ek activity se doosri activity |
| Implicit | Browser, dialer, share, camera jaisi system/other-app actions |
| Extras | Ek activity se doosri me data pass karna |

## Block 5 — XML Layout: TextView, EditText, Button, ImageView

### XML Layout Ka Basic Structure

```xml
<?xml version="1.0" encoding="utf-8"?>
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical"
    android:padding="16dp">

    <TextView
        android:id="@+id/tvTitle"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="@string/app_name"
        android:textSize="24sp"
        android:textStyle="bold" />

    <EditText
        android:id="@+id/etUsername"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:hint="Enter username" />

    <Button
        android:id="@+id/btnLogin"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:text="Login" />

    <ImageView
        android:id="@+id/ivLogo"
        android:layout_width="100dp"
        android:layout_height="100dp"
        android:src="@drawable/ic_logo" />

</LinearLayout>
```

| View | Use |
|------|-----|
| `TextView` | Text dikhana (read-only) |
| `EditText` | User se input lena |
| `Button` | Click action trigger karna |
| `ImageView` | Image/icon dikhana |

> **Tip:** `match_parent` = "jitna parent ki jagah hai utna le lo", `wrap_content` = "sirf apni content jitna le lo". Ye do sabse zyada use hone waale values hain.

> **Yaad Rakho:** Har view ko `android:id="@+id/name"` do agar Java code se access karna hai. ID na di to `findViewById()` / View Binding se access nahi hoga.

## Block 6 — LinearLayout vs ConstraintLayout

### LinearLayout — Ek Line Me Sab Kuch

```xml
<LinearLayout
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:orientation="horizontal">

    <Button android:layout_width="0dp" android:layout_weight="1"
        android:layout_height="wrap_content" android:text="Cancel" />
    <Button android:layout_width="0dp" android:layout_weight="1"
        android:layout_height="wrap_content" android:text="Confirm" />
</LinearLayout>
```

> **Socho Aise:** LinearLayout ek train hai — sab bogiyan ek line me (vertical ya horizontal), koi complex overlap nahi ho sakta.

### ConstraintLayout — Views Ko Ek Doosre Se "Constrain" Karo

```xml
<androidx.constraintlayout.widget.ConstraintLayout
    xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto"
    android:layout_width="match_parent"
    android:layout_height="match_parent">

    <TextView
        android:id="@+id/tvTitle"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Smart Meter"
        app:layout_constraintTop_toTopOf="parent"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintEnd_toEndOf="parent" />

    <Button
        android:id="@+id/btnSync"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:text="Sync Now"
        app:layout_constraintTop_toBottomOf="@id/tvTitle"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintEnd_toEndOf="parent" />

</androidx.constraintlayout.widget.ConstraintLayout>
```

> **Socho Aise:** ConstraintLayout ek carrom board hai — har coin (view) ko doosre coins ya board ke edges se "connect/constrain" karte ho, wo exactly wahi rahega jahan tumne bola.

| | LinearLayout | ConstraintLayout |
|---|---|---|
| Nesting | Complex UI me deep nesting chahiye | Flat hierarchy, better performance |
| Positioning | Sirf ek direction (row/column) | Kisi bhi direction, kisi bhi view se relative |
| Best for | Simple lists, button rows | Real-world screens (recommended default) |

> **Yaad Rakho:** Google khud recommend karta hai naye projects me `ConstraintLayout` default use karo — deep nesting se `LinearLayout` slow ho jaata hai (measure/layout pass zyada baar chalta hai).

## Block 7 — View Binding

### Purana Tarika (Avoid Karo)

```java
TextView tvTitle = findViewById(R.id.tvTitle);   // har view ke liye ye line, error-prone
```

### View Binding — Type-Safe, No `findViewById`

**1. `build.gradle` (app) me enable karo:**
```groovy
android {
    buildFeatures {
        viewBinding true
    }
}
```

**2. Activity me use karo:**
```java
public class MainActivity extends AppCompatActivity {
    private ActivityMainBinding binding;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        binding = ActivityMainBinding.inflate(getLayoutInflater());
        setContentView(binding.getRoot());

        binding.tvTitle.setText("Smart Meter");
        binding.btnLogin.setOnClickListener(v -> {
            // click handle karo
        });
    }
}
```

> **Socho Aise:** View Binding ek auto-generated class hai (`ActivityMainBinding`) jo XML ke har `id` wale view ko ek Java field bana deti hai — spelling galti ya wrong type cast ka crash **compile time** pe hi pakड़ jaata hai, runtime pe nahi.

> **Yaad Rakho:** `findViewById()` runtime pe ID dhoondhta hai (thoda slow, aur galat type cast karne pe crash) — View Binding compile time pe hi sab check kar leta hai. Isiliye modern Android apps me View Binding standard hai.

## Block 8 — Mini Project: Login → Welcome (2-Activity App)

**`activity_login.xml`:**
```xml
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent" android:layout_height="match_parent"
    android:orientation="vertical" android:padding="24dp" android:gravity="center">

    <EditText android:id="@+id/etName" android:layout_width="match_parent"
        android:layout_height="wrap_content" android:hint="Enter your name" />

    <Button android:id="@+id/btnLogin" android:layout_width="match_parent"
        android:layout_height="wrap_content" android:text="Login" android:layout_marginTop="12dp" />
</LinearLayout>
```

**`LoginActivity.java`:**
```java
public class LoginActivity extends AppCompatActivity {
    private ActivityLoginBinding binding;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        binding = ActivityLoginBinding.inflate(getLayoutInflater());
        setContentView(binding.getRoot());

        binding.btnLogin.setOnClickListener(v -> {
            String name = binding.etName.getText().toString();
            if (name.isEmpty()) {
                binding.etName.setError("Naam zaroori hai");
                return;
            }
            Intent intent = new Intent(LoginActivity.this, WelcomeActivity.class);
            intent.putExtra("USER_NAME", name);
            startActivity(intent);
        });
    }
}
```

**`WelcomeActivity.java`:**
```java
public class WelcomeActivity extends AppCompatActivity {
    private ActivityWelcomeBinding binding;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        binding = ActivityWelcomeBinding.inflate(getLayoutInflater());
        setContentView(binding.getRoot());

        String name = getIntent().getStringExtra("USER_NAME");
        binding.tvWelcome.setText("Welcome, " + name + "!");
    }
}
```

**Manifest me dono register karna mat bhoolo**, aur `LoginActivity` ko `MAIN`/`LAUNCHER` banao.

> **Challenge:** `WelcomeActivity` me ek "Logout" button add karo jo `finish()` call kare aur wapas `LoginActivity` pe le jaaye.

## 📋 Quick Revision

| Concept | One-liner |
|---------|-----------|
| AndroidManifest | App ka ID card — components, permissions, launcher activity |
| Activity | Ek class = ek screen |
| Lifecycle | onCreate → onStart → onResume → onPause → onStop → onDestroy |
| A→B Lifecycle | A.onPause → B poori tarah resume → A.onStop |
| Explicit Intent | Apni app ke andar specific activity kholna |
| Implicit Intent | System/doosri app se action karwana (browser, call, share) |
| Intent Extras | `putExtra()` / `getXExtra()` se data pass karna |
| LinearLayout | Ek direction me views (row/column) |
| ConstraintLayout | Views ko relative constraints se position karna (recommended) |
| View Binding | Compile-time safe view access, no `findViewById` |

## 🎯 Interview Tips

1. **Q: Activity A se B pe jaane par lifecycle order kya hoga?**
   *A: A.onPause → B.onCreate → B.onStart → B.onResume → A.onStop.*

2. **Q: `onPause()` me heavy operation kyun nahi karni chahiye?**
   *A: Jab tak `onPause()` complete nahi hota, doosri activity ka `onResume()` nahi chalta — UI slow/laggy dikhega.*

3. **Q: Implicit Intent ka real use case?**
   *A: Jab tumhe exact pata nahi (ya matter nahi karta) kaun-si app handle karegi — jaise "Share" button, jo WhatsApp/Email/koi bhi app khol sakta hai.*

4. **Q: LinearLayout ke bajaye ConstraintLayout kyun prefer karte hain?**
   *A: Flat view hierarchy — deep nesting nahi chahiye, isliye rendering/measure pass fast hota hai complex screens pe.*
