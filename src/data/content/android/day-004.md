## Block 1 — Client-Server Model + HTTP

### Client-Server Kya Hai

```
[Android App]  ──── HTTP Request ────>  [Server]
   (Client)   <──── HTTP Response ────    (API)
```

> **Socho Aise:** Restaurant me tum (Client) waiter ko order (Request) dete ho, kitchen (Server) khaana banake plate (Response) bhejta hai. Tum kitchen ke andar nahi jaate — sirf order aur result se matlab hai.

### 🧠 Theory: URL Type Karne Se Response Aane Tak Kya Hota Hai

Jab app `https://api.example.com/meters` ko call karti hai, background me ye steps hote hain:

1. **DNS Lookup:** `api.example.com` naam ko actual IP address (jaise `142.250.183.14`) me convert karna — phonebook se number dhoondhne jaisa.
2. **TCP Connection:** App aur server ke beech ek reliable connection banta hai (3-way handshake) — jaise call milaana, ring hona, uthana.
3. **TLS/SSL Handshake** (agar HTTPS hai): Connection encrypt hota hai — beech me koi data padh/badal na sake.
4. **HTTP Request Bhejna:** Method, headers, body — sab is connection ke upar bhejе jaate hain.
5. **Server Process Karta Hai:** Database query, business logic, response bana ke wapas bhejta hai.
6. **Response Wapas Aata Hai:** App usse parse karke (JSON → Java object) UI update karti hai.

> **Yaad Rakho:** Ye poora process **milliseconds** me hota hai, par har step pe kuch galat ho sakta hai — DNS fail (no internet), TCP timeout (server down), TLS error (certificate problem). Isi liye Block 7 me alag-alag error types alag se handle karte hain.

### HTTP Kya Hai

**HTTP (HyperText Transfer Protocol)** — rules ka set jo batata hai Client aur Server kaise baat karenge. Har request ek **method**, ek **URL**, kuch **headers**, aur (optional) ek **body** carry karti hai.

```
GET https://api.smartmeter.com/readings/MTR-001
Headers: Authorization: Bearer <token>
```

> **Yaad Rakho:** HTTP **stateless** hai — har request independent hoti hai, server ko pichhli request yaad nahi rehti. Isi wajah se JWT token har request ke saath bhejna padta hai (Day 5 me detail).

## Block 2 — REST API + HTTP Methods

**REST (REpresentational State Transfer)** — API design ka standard style jisme **resources** (jaise `meters`, `readings`) URLs se represent hote hain, aur HTTP methods batate hain unke saath kya karna hai.

```java
// GET — data padhna
GET /api/meters/MTR-001

// POST — naya data banana
POST /api/readings
Body: { "meterId": "MTR-001", "reading": 245.5 }

// PUT — poora resource replace karna
PUT /api/meters/MTR-001
Body: { "meterId": "MTR-001", "status": "active", "location": "Sector 5" }

// PATCH — sirf kuch fields update karna
PATCH /api/meters/MTR-001
Body: { "status": "inactive" }

// DELETE — resource hataana
DELETE /api/readings/45
```

| Method | Kaam | Idempotent? |
|--------|------|-------------|
| `GET` | Data fetch karna | Haan — baar-baar call karo, result same |
| `POST` | Naya resource banana | Nahi — baar-baar call karne se naye records ban sakte hain |
| `PUT` | Poora resource replace | Haan |
| `PATCH` | Partial update | Aksar Haan (depends) |
| `DELETE` | Resource hataana | Haan |

> **Interview Trap:** "PUT vs PATCH" — `PUT` **poora object** bhejta hai (missing fields null ho sakti hain), `PATCH` sirf **jo change karna hai wahi fields** bhejta hai.

> **Socho Aise:** `Idempotent` matlab — same request 1 baar chalao ya 10 baar, result same rehna chahiye. `DELETE /readings/45` 5 baar bhi chalao, wo record ek hi baar delete hoga (agla delete "already gone" bolega) — result same rehta hai.

## Block 3 — Headers, Body, Params, Status Codes

### Headers — Request Ke Baare Me Metadata

```
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Accept: application/json
```

> **Socho Aise:** Headers ek courier parcel ke bahar chipka label hai — "fragile", "cash on delivery", "sender ka pata" — parcel ke andar ka saamaan (body) nahi, uske baare me info.

### Request Body — Actual Data

```json
{
  "meterId": "MTR-001",
  "reading": 245.5,
  "timestamp": 1755680400000
}
```

### Query Parameters — URL Ke Baad `?key=value`

```
GET /api/readings?meterId=MTR-001&limit=20&page=1
```

> **Yaad Rakho:** Query params **filtering, sorting, pagination** ke liye use hote hain — resource identify karne ke liye nahi.

### Path Parameters — URL Ke Andar Hi Value

```
GET /api/meters/MTR-001/readings
                 ^^^^^^^^^ ← ye path parameter hai, kaunsa meter specify kar raha hai
```

| | Query Param | Path Param |
|---|---|---|
| Syntax | `?key=value` | `/resource/{id}` |
| Use | Optional filters, pagination | Zaroori — resource identify karna |
| Example | `?page=2&limit=10` | `/meters/MTR-001` |

### HTTP Status Codes

| Range | Matlab | Common Codes |
|-------|--------|---------------|
| `2xx` | Success | `200 OK`, `201 Created`, `204 No Content` |
| `3xx` | Redirect | `301 Moved`, `304 Not Modified` |
| `4xx` | Client ki galti | `400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found` |
| `5xx` | Server ki galti | `500 Internal Server Error`, `503 Service Unavailable` |

> **Tip:** `401` = "tum kaun ho pata nahi" (token missing/invalid). `403` = "pata hai tum kaun ho, par tumhe permission nahi" (Day 5 ke JWT topic me clear hoga).

## Block 4 — JSON + Gson

### JSON — Data Exchange Ka Universal Format

```json
{
  "meterId": "MTR-001",
  "reading": 245.5,
  "isActive": true,
  "tags": ["residential", "sector-5"],
  "owner": { "name": "Ashutosh", "id": 101 }
}
```

### Gson — JSON ↔ Java Object

```java
public class MeterReadingResponse {
    String meterId;
    double reading;
    boolean isActive;
    List<String> tags;
    Owner owner;

    static class Owner {
        String name;
        int id;
    }
}
```

```java
import com.google.gson.Gson;

Gson gson = new Gson();

// JSON String → Java Object
String json = "{\"meterId\":\"MTR-001\",\"reading\":245.5}";
MeterReadingResponse response = gson.fromJson(json, MeterReadingResponse.class);

// Java Object → JSON String
String backToJson = gson.toJson(response);
```

> **Socho Aise:** Gson ek translator hai — server "JSON language" bolta hai, Java "Object language" bolta hai. Gson beech me khada ho kar dono taraf translate karta hai.

> **Yaad Rakho:** JSON field names **exact match** karne chahiye Java field names se (ya `@SerializedName("meter_id")` annotation use karo agar naming alag ho — jaise server `snake_case` bhejta hai, Java `camelCase` use karta hai).

```java
public class MeterReadingResponse {
    @SerializedName("meter_id")
    String meterId;
}
```

## Block 5 — Retrofit Setup + GET/POST

### Retrofit Kya Hai

Retrofit ek library hai jo REST API calls ko **type-safe Java interfaces** me convert kar deti hai — manual URL banane, JSON parse karne ki zaroorat nahi.

### Setup

```groovy
// build.gradle (app)
implementation 'com.squareup.retrofit2:retrofit:2.9.0'
implementation 'com.squareup.retrofit2:converter-gson:2.9.0'
```

### API Interface Define Karo

```java
public interface MeterApiService {

    @GET("meters/{meterId}")
    Call<MeterReadingResponse> getMeter(@Path("meterId") String meterId);

    @GET("readings")
    Call<List<MeterReadingResponse>> getReadings(
            @Query("meterId") String meterId,
            @Query("limit") int limit
    );

    @POST("readings")
    Call<MeterReadingResponse> submitReading(@Body MeterReadingRequest request);

    @PUT("meters/{meterId}")
    Call<MeterReadingResponse> updateMeter(@Path("meterId") String meterId, @Body MeterReadingRequest request);

    @DELETE("readings/{id}")
    Call<Void> deleteReading(@Path("id") int id);
}
```

### Retrofit Instance Banao

```java
public class RetrofitClient {
    private static Retrofit retrofit;
    private static final String BASE_URL = "https://api.smartmeter.com/";

    public static Retrofit getInstance() {
        if (retrofit == null) {
            retrofit = new Retrofit.Builder()
                    .baseUrl(BASE_URL)
                    .addConverterFactory(GsonConverterFactory.create())
                    .build();
        }
        return retrofit;
    }
}
```

### API Call Karna (Async)

```java
MeterApiService api = RetrofitClient.getInstance().create(MeterApiService.class);

Call<MeterReadingResponse> call = api.getMeter("MTR-001");
call.enqueue(new Callback<MeterReadingResponse>() {
    @Override
    public void onResponse(Call<MeterReadingResponse> call, Response<MeterReadingResponse> response) {
        if (response.isSuccessful() && response.body() != null) {
            MeterReadingResponse meter = response.body();
            Log.d("API", "Reading: " + meter.reading);
        } else {
            Log.e("API", "Error code: " + response.code());
        }
    }

    @Override
    public void onFailure(Call<MeterReadingResponse> call, Throwable t) {
        Log.e("API", "Network failed: " + t.getMessage());
    }
});
```

> **Yaad Rakho:** `.enqueue()` **asynchronous** hai — background thread pe chalta hai, result callback me aata hai. `.execute()` **synchronous** hai — main thread pe kabhi mat use karo, warna `NetworkOnMainThreadException` crash milega.

> **Socho Aise:** `enqueue()` = Zomato order dena aur apna kaam karte rehna, delivery aane pe doorbell (callback) bajegi. `execute()` = khud kitchen me khade rehke khaana bante dekhna — kitchen jaam ho jaayega (UI thread block).

## Block 6 — OkHttp + Interceptor

Retrofit ke andar actually **OkHttp** hi network calls karta hai — Retrofit sirf ek convenient layer hai upar.

### Interceptor — Har Request/Response Ko "Intercept" Karna

```java
public class LoggingInterceptor implements Interceptor {
    @NonNull
    @Override
    public Response intercept(@NonNull Chain chain) throws IOException {
        Request request = chain.request();
        Log.d("OkHttp", "Sending request: " + request.url());

        Response response = chain.proceed(request);   // actual call yahan hoti hai

        Log.d("OkHttp", "Response code: " + response.code());
        return response;
    }
}
```

```java
OkHttpClient client = new OkHttpClient.Builder()
        .addInterceptor(new LoggingInterceptor())
        .connectTimeout(30, TimeUnit.SECONDS)
        .readTimeout(30, TimeUnit.SECONDS)
        .build();

Retrofit retrofit = new Retrofit.Builder()
        .baseUrl(BASE_URL)
        .client(client)               // OkHttpClient ko Retrofit me plug karo
        .addConverterFactory(GsonConverterFactory.create())
        .build();
```

> **Socho Aise:** Interceptor ek security guard hai jo har parcel (request) ko gate se bahar jaane se pehle check karta hai (ya andar aane pe check karta hai) — logging, headers add karna, retry logic — sab yahi ho sakta hai.

> **Tip:** Day 5 me JWT token automatically har request me attach karne ke liye bhi **Interceptor** hi use hoga — ye pattern bahut important hai.

## Block 7 — API Error Handling

```java
call.enqueue(new Callback<MeterReadingResponse>() {
    @Override
    public void onResponse(Call<MeterReadingResponse> call, Response<MeterReadingResponse> response) {
        if (response.isSuccessful()) {
            // 2xx — success
            handleSuccess(response.body());
        } else if (response.code() == 401) {
            // token expired/invalid
            redirectToLogin();
        } else if (response.code() == 404) {
            showError("Meter not found");
        } else if (response.code() >= 500) {
            showError("Server error, try again later");
        } else {
            showError("Something went wrong: " + response.code());
        }
    }

    @Override
    public void onFailure(Call<MeterReadingResponse> call, Throwable t) {
        if (t instanceof SocketTimeoutException) {
            showError("Request timed out — check your connection");
        } else if (t instanceof IOException) {
            showError("No internet connection");
        } else {
            showError("Unexpected error: " + t.getMessage());
        }
    }
});
```

| Case | Callback | Kaise Handle Karo |
|------|----------|---------------------|
| Server ne response diya (chahe error ho) | `onResponse()` | `response.code()` check karo |
| Network hi fail ho gaya (no internet, timeout) | `onFailure()` | `Throwable` ka type check karo |

> **Yaad Rakho:** `404` ya `500` bhi `onResponse()` me hi aate hain (`onFailure()` me nahi) — kyunki server ne actually respond kiya, bas error ke saath. `onFailure()` sirf tab chalta hai jab server tak request **pahunch hi nahi payi**.

## Block 8 — Mini Project: Meter API Client

```java
public interface MeterApiService {
    @GET("meters")
    Call<List<MeterReadingResponse>> getAllMeters();

    @POST("readings")
    Call<MeterReadingResponse> submitReading(@Body MeterReadingRequest request);
}

public class MeterRepository {
    private final MeterApiService api;

    public MeterRepository() {
        api = RetrofitClient.getInstance().create(MeterApiService.class);
    }

    public void fetchAllMeters(RepositoryCallback<List<MeterReadingResponse>> callback) {
        api.getAllMeters().enqueue(new Callback<List<MeterReadingResponse>>() {
            @Override
            public void onResponse(Call<List<MeterReadingResponse>> call, Response<List<MeterReadingResponse>> response) {
                if (response.isSuccessful() && response.body() != null) {
                    callback.onSuccess(response.body());
                } else {
                    callback.onError("Error: " + response.code());
                }
            }
            @Override
            public void onFailure(Call<List<MeterReadingResponse>> call, Throwable t) {
                callback.onError("Network failed: " + t.getMessage());
            }
        });
    }

    public interface RepositoryCallback<T> {
        void onSuccess(T data);
        void onError(String message);
    }
}
```

> **Challenge:** `submitReading()` method ka poora flow likho — Activity se call kare, `MeterRepository` Retrofit se POST kare, aur success/error UI me dikhe.

## 📋 Quick Revision

| Concept | One-liner | Kahan Use Hoga (Smart Meter Project Me) |
|---------|-----------|-------------------------------------------|
| Client-Server | App request bhejta hai, server response deta hai | App ↔ backend server ka poora communication model |

## 🎯 Interview Tips

1. **Q: `enqueue()` vs `execute()`?**
   *A: `enqueue()` async (background thread, callback), `execute()` sync (main thread pe crash karega — kabhi mat use karo).*

2. **Q: 404 error `onFailure()` me aayega ya `onResponse()` me?**
   *A: `onResponse()` me — server ne respond kiya hai (error ke saath). `onFailure()` sirf connectivity/timeout jaisi cheezon ke liye.*

3. **Q: Interceptor kis liye use karte ho real apps me?**
   *A: Logging, JWT token auto-attach karna, common headers add karna, retry logic.*

4. **Q: PUT vs PATCH?**
   *A: PUT poora resource replace karta hai, PATCH sirf specified fields update karta hai.*
