# 🌅 HOUR 1 — CONCEPT

## Why Dependency Injection?

Manual wiring (Day 34) chote project me OK. Bade me:
- Same instance multiple jagah chahiye (e.g., UserRepository everywhere)
- Tests me mock chahiye
- Lazy initialization (bana when needed)

> **Solution:** **Service locator** — central registry, code anywhere se dependencies fetch karta hai.

## Registration Types

### 1. Singleton (One instance forever)

```dart
getIt.registerSingleton<AuthRepository>(AuthRepositoryImpl(/* deps */));
```

### 2. LazySingleton (Created on first access)

```dart
getIt.registerLazySingleton<AuthRepository>(() => AuthRepositoryImpl(/* deps */));
```

### 3. Factory (New instance every time)

```dart
getIt.registerFactory<AuthBloc>(() => AuthBloc(useCase: getIt<LoginUseCase>()));
```

| Type | When |
|------|------|
| **Singleton** | Stateless services (Repository, ApiClient) |
| **LazySingleton** | Heavy services not always needed |
| **Factory** | Stateful objects per-screen (Bloc, ViewModel) |

## injection_container.dart Pattern

```dart
// lib/core/di/injection.dart
import 'package:get_it/get_it.dart';

final getIt = GetIt.instance;

Future<void> setupDI() async {
  // ---- External ----
  getIt.registerLazySingleton(() => http.Client());
  final prefs = await SharedPreferences.getInstance();
  getIt.registerSingleton(prefs);

  // ---- Data ----
  getIt.registerLazySingleton<AuthRemoteDataSource>(
    () => AuthRemoteDataSourceImpl(client: getIt()),
  );

  // ---- Domain ----
  getIt.registerLazySingleton<AuthRepository>(
    () => AuthRepositoryImpl(remoteDataSource: getIt()),
  );

  getIt.registerLazySingleton(() => LoginUseCase(getIt()));
  getIt.registerLazySingleton(() => LogoutUseCase(getIt()));

  // ---- Presentation ----
  getIt.registerFactory(() => AuthBloc(loginUseCase: getIt()));
}

// main.dart
void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await setupDI();
  runApp(const MyApp());
}
```

> **Hierarchy:** External → Data → Domain → Presentation. Earlier ones available to later registrations.

## Task 1: Auth Feature with get_it (45 min)

### File: lib/core/di/injection.dart

```dart
import 'package:get_it/get_it.dart';
import 'package:http/http.dart' as http;
import '../../features/auth/data/datasources/auth_remote_datasource.dart';
import '../../features/auth/data/repositories/auth_repository_impl.dart';
import '../../features/auth/domain/repositories/auth_repository.dart';
import '../../features/auth/domain/usecases/login_usecase.dart';
import '../../features/auth/presentation/bloc/auth_bloc.dart';

final getIt = GetIt.instance;

Future<void> setupDI() async {
  // External
  getIt.registerLazySingleton(() => http.Client());

  // Data layer
  getIt.registerLazySingleton<AuthRemoteDataSource>(
    () => AuthRemoteDataSourceImpl(client: getIt()),
  );

  // Domain layer
  getIt.registerLazySingleton<AuthRepository>(
    () => AuthRepositoryImpl(remoteDataSource: getIt()),
  );

  // UseCases
  getIt.registerLazySingleton(() => LoginUseCase(getIt()));

  // Presentation (Factory — new instance per screen)
  getIt.registerFactory(() => AuthBloc(loginUseCase: getIt()));
}
```

### Update main.dart

```dart
void main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await setupDI();
  runApp(const MyApp());
}
```

### Use in Login Screen

## Task 2: Mock for Tests (15 min)

```bash
flutter pub add --dev mocktail
```

```dart
// test/auth/login_usecase_test.dart
import 'package:flutter_test/flutter_test.dart';
import 'package:mocktail/mocktail.dart';
import 'package:get_it/get_it.dart';

class MockAuthRepository extends Mock implements AuthRepository {}

void main() {
  late MockAuthRepository mockRepo;

  setUp(() {
    GetIt.I.reset();
    mockRepo = MockAuthRepository();
    GetIt.I.registerLazySingleton<AuthRepository>(() => mockRepo);
  });

  test('login returns user on success', () async {
    when(() => mockRepo.login('admin@app.com', 'admin123'))
        .thenAnswer((_) async => const User(id: '1', name: 'Admin', email: 'admin@app.com'));

    final useCase = LoginUseCase(GetIt.I<AuthRepository>());
    final result = await useCase('admin@app.com', 'admin123');

    expect(result, isNotNull);
    expect(result!.email, 'admin@app.com');
  });

  test('login throws on invalid email', () async {
    final useCase = LoginUseCase(MockAuthRepository());

    expect(() => useCase('not-an-email', 'pass123'), throwsException);
  });
}
```

## ❌ Common Mistakes

```dart
// MISTAKE 1: Async setup not awaited
runApp(MyApp());  // before setupDI()
// FIX: await setupDI() pehle

// MISTAKE 2: Wrong registration type
getIt.registerSingleton<Bloc>(...);  // ❌ same Bloc shared all screens (state bug)
// FIX: registerFactory for Bloc/ViewModel

// MISTAKE 3: Cyclic dependency
A depends on B, B depends on A
// FIX: Refactor — extract shared interface

// MISTAKE 4: No reset between tests
// → mock state leaks across tests
// FIX: getIt.reset() in setUp
```

## 🎯 Interview Tips

1. **Q: Service locator vs constructor injection?**
   *A: Service locator — global, easy. Constructor — explicit dependencies, easier to test. get_it me both possible.*

2. **Q: Singleton vs Factory in get_it?**
   *A: Singleton — same instance everywhere (services). Factory — new instance each time (Blocs).*

3. **Q: get_it ko replace karne ke liye options?**
   *A: provider/Riverpod (built-in DI), injectable (codegen on top of get_it), riverpod (no service locator pattern).*

4. **Q: Lazy vs Eager singleton?**
   *A: Eager — created at registration. Lazy — first access pe. Heavy services lazy.*
