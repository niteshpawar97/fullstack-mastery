# 🌅 HOUR 1 — CONCEPT

## Clean Architecture Kya Hai?

Code ko **3 layers** me organize karne ka pattern by Uncle Bob. Code maintainable + testable + scalable.

> **Socho Aise:** Restaurant me 3 roles — **Chef** (kitchen, business logic), **Storekeeper** (data fetch, DB/API), **Waiter** (presentation, customer). Sab apna kaam karte hain. Code me bhi same.

---

## 3 Layers

### 1. Domain (Pure Business)
**Pure Dart**. No Flutter, no API, no DB.
- **Entities:** Pure data classes
- **UseCases:** Business actions
- **Repository interfaces:** Abstract contracts

### 2. Data (External World)
APIs, databases, cache.
- **Models:** With serialization
- **DataSources:** REST/Firestore/SQLite implementations
- **Repository impls:** Concrete classes

### 3. Presentation (UI)
Flutter widgets, Bloc, navigation.
- **Blocs/Cubits**
- **Screens, Widgets**

## Dependency Rule

```
Presentation → Domain ← Data
```

- Outer layers (Presentation, Data) → depend on Domain
- Domain → depends on **nothing**

> **Magic:** Domain change na ho — UI ya Data change karte raho.

### usecases/login_usecase.dart

```dart
class LoginUseCase {
  final AuthRepository repository;

  LoginUseCase(this.repository);

  Future<User?> call(String email, String password) {
    if (!email.contains('@')) throw Exception('Invalid email');
    if (password.length < 6) throw Exception('Password too short');
    return repository.login(email, password);
  }
}
```

## 2. Data Layer

### models/user_model.dart

```dart
import '../../domain/entities/user.dart';

class UserModel extends User {
  const UserModel({required super.id, required super.name, required super.email});

  factory UserModel.fromJson(Map<String, dynamic> json) {
    return UserModel(
      id: json['id'] as String,
      name: json['name'] as String,
      email: json['email'] as String,
    );
  }

  Map<String, dynamic> toJson() => {'id': id, 'name': name, 'email': email};
}
```

> **UserModel extends User** — entity (Domain) + serialization (Data).

### repositories/auth_repository_impl.dart

```dart
import '../../domain/entities/user.dart';
import '../../domain/repositories/auth_repository.dart';
import '../datasources/auth_remote_datasource.dart';

class AuthRepositoryImpl implements AuthRepository {
  final AuthRemoteDataSource remoteDataSource;
  User? _currentUser;

  AuthRepositoryImpl({required this.remoteDataSource});

  @override
  Future<User?> login(String email, String password) async {
    final userModel = await remoteDataSource.login(email, password);
    _currentUser = userModel;
    return userModel;
  }

  @override
  Future<void> logout() async {
    _currentUser = null;
  }

  @override
  User? get currentUser => _currentUser;
}
```

## 3. Presentation Layer

### bloc/auth_bloc.dart

```dart
import '../../domain/usecases/login_usecase.dart';

class AuthBloc extends Bloc<AuthEvent, AuthState> {
  final LoginUseCase loginUseCase;

  AuthBloc({required this.loginUseCase}) : super(AuthInitial()) {
    on<AuthLoginRequested>((event, emit) async {
      emit(AuthLoading());
      try {
        final user = await loginUseCase(event.email, event.password);
        if (user != null) emit(AuthSuccess(user));
        else emit(const AuthFailure('Invalid credentials'));
      } catch (e) {
        emit(AuthFailure(e.toString()));
      }
    });
  }
}
```

> Bloc me sirf state mgmt + UseCase invocation. Repository ka direct knowledge nahi.

## Task 1: Refactor Counter into 3 Layers (40 min)

### Domain

```dart
// features/counter/domain/entities/counter.dart
class Counter {
  final int value;
  const Counter(this.value);
}

// features/counter/domain/repositories/counter_repository.dart
abstract class CounterRepository {
  Counter get current;
  Counter increment();
  Counter decrement();
  Counter reset();
}

// features/counter/domain/usecases/increment_counter.dart
class IncrementCounter {
  final CounterRepository repo;
  IncrementCounter(this.repo);
  Counter call() => repo.increment();
}

class DecrementCounter {
  final CounterRepository repo;
  DecrementCounter(this.repo);
  Counter call() => repo.decrement();
}
```

### Data

```dart
// features/counter/data/repositories/counter_repository_impl.dart
class InMemoryCounterRepository implements CounterRepository {
  Counter _current = const Counter(0);

  @override
  Counter get current => _current;

  @override
  Counter increment() {
    _current = Counter(_current.value + 1);
    return _current;
  }

  @override
  Counter decrement() {
    _current = Counter(_current.value - 1);
    return _current;
  }

  @override
  Counter reset() {
    _current = const Counter(0);
    return _current;
  }
}
```

### Presentation

```dart
// features/counter/presentation/bloc/counter_cubit.dart
class CounterCubit extends Cubit<int> {
  final IncrementCounter increment;
  final DecrementCounter decrement;

  CounterCubit({required this.increment, required this.decrement}) : super(0);

  void inc() => emit(increment().value);
  void dec() => emit(decrement().value);
}
```

### Composition Root (main.dart)

```dart
void main() {
  final repository = InMemoryCounterRepository();
  final increment = IncrementCounter(repository);
  final decrement = DecrementCounter(repository);

  runApp(
    BlocProvider(
      create: (_) => CounterCubit(increment: increment, decrement: decrement),
      child: const MyApp(),
    ),
  );
}
```

> **Test benefit:** Repository mock karke UseCase test isolated. Bloc test fake UseCase pass karke.

## ❌ Common Mistakes

```dart

class User { final Color color = Colors.red; }  // ❌
// FIX: Pure Dart only

// MISTAKE 2: Bloc directly using HTTP
class AuthBloc { http.get(...); }  // ❌
// FIX: Through UseCase → Repository

// MISTAKE 3: Over-engineering
// 50-line app me 3 layers = overkill
// FIX: Use only when complexity justifies
```

## 🎯 Interview Tips

1. **Q: Clean Architecture me Domain layer kya hai?**
   *A: Pure business logic — entities + usecases + abstract repos. No framework dependencies.*

2. **Q: Dependency rule kya hai?**
   *A: Inward — outer layers depend on inner. Domain pe nothing depends.*

3. **Q: UseCase aur Repository me kya farq?**
   *A: Repository — data access (CRUD). UseCase — business action.*

4. **Q: Clean architecture overkill kab hai?**
   *A: Single-feature small apps me. Multi-team, long-lived apps me worth it.*
